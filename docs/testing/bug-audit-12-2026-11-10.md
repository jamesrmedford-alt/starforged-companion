### The Private Channel and Private Lines

#### AA02 · PRIVATE-CHANNEL-WINDOW-RENDERS-NOTHING — high · UX

**In one line.** The ✦ Private Channel window has no _replaceHTML, so in Foundry it opens with an empty content area — no transcript, no text box, no Send or Publish (Foundry: one live check).

**What happens (SWP-3).** The ✦ Private Channel window has no _replaceHTML. Foundry's ApplicationV2 renders in two steps — _renderHTML builds the result and _replaceHTML puts it into the window — and the base class implements neither (a subclass "should implement this method in order for the Application to be renderable"). PrivateChannelApp builds its element and nothing inserts it, so in a live world the window opens with an empty content area: no transcript, no text box, no Send or Publish. It is the only one of the module's fourteen ApplicationV2 windows without one, and it was already so at the eleventh audit's base (8a4ae3b). The unit harness cannot see it: tests/setup.js's ApplicationV2 stub render() is a no-op, the Quench Private Channel batch builds the context without opening the window, and no playtest finding mentions the Private Channel. Found by the two round-2 refuters of R2T-2 (PRIVATE-CHANNEL-REFRESH-WIPES-TYPING); the typed-line wipe R2T-2 filed is what a naive _replaceHTML would expose under Z66's refresh, so the fix must keep typed input.
